| `REV#121` | [The first configure downloads a CMake and a PowerShell although Visual Studio has just installed both](FINDINGS.md#rev121) | First step done 2026-11-13 ([record](2026-11-13-vcpkg-tool-downloads.md)). No port asks for either tool. vcpkg fetches both because every package's ABI hash records their versions. Visual Studio 2026's vcpkg (2026-05-27) asks for CMake 4.3.2 and PowerShell 7.5.4. Visual Studio ships CMake 4.3.1-msvc1 and installs no PowerShell 7. Four starter configures were run, each with empty download and binary caches. With no setting, 53 MB of CMake and 117 MB of PowerShell were downloaded. With VCPKG_FORCE_SYSTEM_BINARIES=1, configure failed after 9 s with no PowerShell 7 on PATH. With the setting and a PowerShell 7 on PATH, nothing was downloaded and the project built and both tests passed. With a PowerShell 7 on PATH and no setting, only CMake was downloaded. No setting removes both downloads for a reader who has only installed the prerequisites. The setting also blocks the private Git download; this was inferred and not run. The starter and Build Labrador pages no longer call Visual Studio's PowerShell unsuitable, because it has none. Whether to change the starter is the owner's call. |
