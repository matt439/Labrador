# Features other 2D engines have: the comparison re-checked, 2026-11-10

**A dated record, as written, not updated as items land.** It re-checks
[the comparison of 2026-10-27](2026-10-27.md) against sources, and adds the C
and C++ frameworks that comparison left out. It decides nothing. Each open item
is still a `GAP#` row in [TODO.md](../../TODO.md), which is where its state
lives, and every row is still the owner's call.

The earlier comparison said of itself that the other engines' side was
"written from knowledge of their current releases and not re-checked against
their documentation, so the counts below are approximate". This record does
that check. For each of its seventeen rows and each engine it gives one
answer and one source, read on 2026-11-10 at that engine's latest release.
Ten of the seventeen counts change and seven stand; [The counts](#the-counts)
lists each correction.

## Method

**What was fetched.** Source files and documentation sources from each
project's own repository on GitHub, at the tag of its latest release as
GitHub's release API reported it on 2026-11-10: public headers, the engine
source that defines a scripting API, class-reference XML, manual pages and
build manifests. About 220 files. sokol publishes no releases and was read at
the head of its default branch. Defold's manuals live in a second repository
with no tags and were read at its head.

**What an answer means.** *yes*: the linked line declares or documents the
feature in the core or an official first-party library, which is the earlier
comparison's rule. *partly*: something narrower is there, and the last column
says what. *no*: a text search of the files fetched for that project found
nothing, and where the release's list of file names was also fetched (every
project but SDL, FNA, Godot and Defold's engine) no file is named for it
either. A "no" link points at the file where the feature would most naturally
be.

**Limits.**

- Nothing was compiled or run. A "yes" is a declaration or a sentence of
  documentation, not observed behaviour.
- A "no" is weaker than a "yes". It is the absence of a match in a subset of
  each repository, chosen by where the feature would be. It is not a search of
  the whole project.
  A second reading before this record was committed overturned three such
  answers (MonoGame's and Defold's `RNG`, Cute Framework's `GAP#8`); others
  may be wrong the same way.
- A cell marked † rests wholly or partly on knowledge, not on a line that was
  read. Its last column says which part. There are fourteen.
- Two documentation sites could not be read. `love2d.org/wiki` answered 403
  to the fetch, so LÖVE's side is its C++ source, which registers every
  function its Lua API has. `defold.com/ref` answered with a moved-page stub,
  so Defold's API is read from the documentation comments in its engine
  source, which is what that reference is generated from, and from the manual
  pages in `defold/doc`.
- LÖVE's latest release is three years old. Its development branch was not
  read.
- MonoGame differs by platform. Only its desktop GL platform files were read
  for pads and music.
- olcPixelGameEngine's separate sound library and Cute Framework's
  documentation site were not read. Third-party extensions were not counted
  for any project, as before.
- Three rows are worded more narrowly than on 2026-10-27, because the source
  forced a choice. `RNG` counts a generator the project ships, not the host
  language's. `GAP#2` counts a compressed file decoded as it plays, whether or
  not it is also read from disk in pieces, since the cost the row is about is
  holding decoded PCM. `GAP#11` counts tilemaps; an importer for Tiled's
  format is stated separately, because no project read here ships one.

What the corrections are:

- **`CUR`, 7 to 4.** raylib, MonoGame and Defold hide or lock the cursor but
  have no call that keeps a visible cursor inside the window.
- **`ADD`, 7 to 6.** Bevy's sprite and 2D material alpha modes are opaque,
  mask and blend. Its additive mode is on the material type its 3D renderer
  uses.
- **`GAP#1`, 7 to 6.** raylib reads SDL's mapping database but is compiled
  for four pads unless rebuilt.
- **`GAP#5`, 7 to 5.** Defold clips GUI nodes with the stencil buffer, and
  Bevy clips UI nodes; neither clips sprites to a rectangle inside a view.
- **`GAP#6`, 5 to 4.** SDL and MonoGame draw caller-built triangles, and
  Defold draws debug lines. None of the three has a circle call; the other
  four do.
- **`GAP#8`, 4 to 3.** Godot, Defold and Bevy ship named easings. raylib's
  are a header among its examples, and MonoGame has a keyed curve type. Of
  the six added frameworks only Cute Framework ships a set.
- **`GAP#9`, 5 to 6.** MonoGame and LÖVE have no camera type and rotate the
  view through a transform. Defold's and Bevy's answers rest partly on
  knowledge.
- **`GAP#11`, 2 to 3.** Bevy now has a tilemap chunk renderer. No project
  read ships an importer for Tiled's format; Defold's manual points at
  Tiled's own exporter.
- **`GAP#12`, 7 to 6.** MonoGame bakes TrueType into a sprite font at build
  time and rasterises nothing at run time, which is Labrador's arrangement
  with a different tool.
- **`GAP#13`, 7 to 6.** FNA has a relative mode and MonoGame's `Mouse` does
  not.

`RNG` stands at 6, and Bevy is the one without: MonoGame ships a PCG32
generator of its own beside .NET's, and Defold replaces Lua's `math.random`
with the engine's.

What the added six show: SFML and Allegro have nearly every drawing and
window row, and neither has seeded random numbers, nine-slice, easing,
particles or tilemaps. sokol is a layer lower than the rest: no image
reader, no audio decoder and no pads. olcPixelGameEngine has neither pads nor
compressed music. `GAP#7`, `GAP#3`, `GAP#4` and additive blending are the
rows nearly everything has; `GAP#10` and `GAP#11` are the rows nearly nothing
code-first has, and of the eight C and C++ frameworks only Cute Framework
has named easings in its library (`GAP#8`).
