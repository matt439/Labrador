# Demo host failure policy: source verification

L7 (`BDP-15` to `BDP-17`) and L8 (`BDP-11` to `BDP-14`) are implemented, and
the packaged page passed the updated `LineSweeperBundlePageTests` on
2026-10-29 ([runtime acceptance](#runtime-acceptance-2026-10-29)). This record
does not qualify a physical pad, a real tab switch, a real driver context
loss, another browser or the hosted deployment.

## Player behaviour

Play checks WebAssembly exception support and WebGL2 before importing the
module. The exception probe contains a function with legacy `try`/`catch_all`,
matching `-fwasm-exceptions` in `cmake/settings.cmake`; it does not require the
newer `exnref` encoding. The scratch graphics context is released with
`WEBGL_lose_context` when available. No probe runs on page load.

An unsupported browser gets advice to update its browser or enable hardware
acceleration, with no retry button or module import. A failed import gives
connection/retry advice. An initialization failure gives startup advice, and
an error after the engine's first scheduled browser frame says the game
stopped. Classification follows the lifecycle stage, never the error's words.
The first scheduled frame is a lifecycle boundary, not evidence that pixels
were drawn. Original diagnostics go to the console, outside the player text.

An error reported synchronously by `onError` keeps its original diagnostic if
the factory promise later rejects. Callbacks and a pending frame from an ended
instance cannot overwrite the next game's status.

## Checks and remaining acceptance

`node --test tests/render/web/bundle_host.test.mjs` passes 23 cases against the
source page's script, substituting the DOM, graphics and module-import
boundaries. The real Node WebAssembly validator accepts the probe bytes. Cases
cover unsupported exceptions and graphics, an absent WebAssembly object,
graphics-context refusal by exception, download retry, factory rejection,
startup and runtime callbacks, replay, stale callbacks, controls and the phone
gate's keyboard/controller routes, bounded context warnings and recovery races. These are synthetic
host-policy checks; they load no generated game module and create no GPU.
CI lint and the existing wasm `BrowserProtocolTests` entry include the suite.

The combined host, bundle-verification and browser-protocol run passes 87
offline cases. All five standalone CMake checks pass. Website check reports
zero errors or warnings, all 157 website tests pass, and the build completes
143 pages with valid internal links. The build reports upstream Vite
`astro:head-inject` directive warnings; no website dependency was changed.

`tests/render/web/bundle_input.mjs` asserts the player-facing wording for each
failure class in the packaged page: a failed loader download (served as 404),
startup (truncated wasm), runtime (`onError`), and two unsupported-browser
cases with no loader or wasm request.

## Focus, controls and the phone gate (L8)

`PlayState` uses `Keyboard::just_unfocused()` before the rules tick to open
the pause menu. Deactivation queues the same menu immediately; a hide/return
with no intervening update therefore remains paused. A covered match does
not stack menus, inactive initialization starts paused, and a topped-out
match keeps its existing result screen. Returning focus does not resume play.
Pads still follow page visibility, not canvas focus; no engine policy changed.

Five new cases in `focus_pause_tests.cpp` exercise the real play/pause states
under native null render/audio in `LineSweeperViewTests`. The Debug-null target
builds and its CTest entry passes. The cases initialize Application services
and a hidden Win32 window, load the checked-in sample content, and use an
independent StateContext with synthetic input and activation. They run no
application loop, graphics/audio API device or physical input.

The additional wasm Release object check stopped while setting up Emscripten:
`C:\Tools\emsdk\emsdk_env.bat` attempted to write
`C:\Tools\emsdk\emsdk_set_env.bat` and Python reported `PermissionError:
[Errno 13] Permission denied`. The object compile did not start. That operation
is stopped, with no alternate environment or compiler route attempted. The
passing native-null build does not establish clang/wasm compilation.

The host's desktop instructions now name every fixed action and its keyboard
and controller bindings, including soft drop, both rotation directions and
pause. The existing in-game hint strings and bindings did not change, so no
capture pixels moved. The coarse-pointer page starts with device instructions.
A keyboard key or a pressed controller button exposes Play without importing
the module or probing graphics. A connection with no pressed button keeps the
gate closed. Controller polling stops when the gate opens; a page policy that
forbids pad access leaves the keyboard route available.

The bundle-page cases assert the two instruction surfaces, the fake-pad
gate route, and quitting from the existing pause menu after canvas blur or
synthetic hide/return, without first pressing Escape. A synthetic visibility
event is not a real tab switch, and a fake pad is not physical-pad
acceptance; both remain `OCA-48`/`BDP-06`'s.

The stale-callback guards make no resource-release claim. Release after a
quit is `BDP-18`'s, measured and fixed in
[web-to-be-tested.md](web-to-be-tested.md#repeated-play-bdp-18-measured-2026-10-29).

## Bounded graphics warning (BDP-16)

Context loss immediately styles the status as a warning. After ten seconds
without restoration, the page offers **Try again**, with a sentence explaining
that graphics have not returned. Restoration cancels the timer and clears the
warning, including when it arrives after the offer. Quit, error and a failed
factory promise also cancel the wait; stale callbacks cannot replace the next
game's status. Factory resolution does not erase an initialization-time context
warning or move focus off an offered button. A late restore returns focus from
that now-hidden button to the canvas; the match's pause policy still requires
an explicit resume.

Try again ends the old game before mounting a fresh one. Removing a running
module's canvas would not stop its loop, so the page calls the instance's
`_linesweeper_quit()`, a sample-owned bridge in `samples/linesweeper/main_web.cpp`
to `Application::quit()`. `onQuit` follows synchronously, the instance releases
itself on the next task (`BDP-18`), and the page mounts a new canvas and
instance through the Play-again path. When the resolved instance has no
bridge, or the call throws or does not reach `onQuit`, the offer is **Reload
page** and the whole document is replaced, so a live instance is never
abandoned. No engine API changed for this.

Offline host cases check warning styling, a single timer, early and late
restoration, retained canvas, the restart through the bridge, the reload
fallback without a bridge and with one that never quits or throws,
quit/error cleanup and a factory rejection after timeout.

## Runtime acceptance (2026-10-29)

`LineSweeperBundlePageTests` passed in `wasm-release` and `wasm-debug` on this
desktop: headless Chrome 156, ANGLE on Direct3D 11, RTX 5080. Its ten cases
cover the touch and controller gates, the unsupported-browser advice with no
module request, the accessibility note and Tab leaving the game, play with a
real `WEBGL_lose_context` loss and restoration, quit after blur and after a
synthetic hide/return without Escape, five repeated games, the unreturned
context's Try again remount, and the download, startup and runtime failure
wording. The offline host suite passes 26 cases. Real GPU resets, physical
pads, real tab switches, Firefox and Safari are not claimed here.
