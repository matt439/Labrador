This page is on the Git route, after [Build Labrador](/docs/get-started/build-labrador/). With
the [starter project](/docs/get-started/starter/), your game is this sample already; read
[What you are looking at](#what-you-are-looking-at) below for what its code does. To run this
sample, LineSweeper or the others from a starter project, follow
[Run the samples](/docs/guides/samples/).

The build you just ran also built the minimal sample. Start it from the `Labrador` folder, in the
same x64 Native Tools Command Prompt. If you closed that window, open a new one and run the
`cd` line first; otherwise the second line is enough:

```bat
cd /d C:\dev\Labrador
out\build\x64-debug\samples\minimal\MinimalSample.exe
```

The prompt is ready for the next command as soon as the window opens; the sample keeps running
until you quit it. If the prompt answers `The system cannot find the path specified.` or says
the program `is not recognized as an internal or external command`, the build in the previous
step did not finish: run `cmake --build --preset x64-debug` again and read its last lines.

A 1280×720 window opens with the line *Hello from the engine.* circling a point, and a hint
along the bottom. Move the point with the left stick of a gamepad, the arrow keys or WASD. Press
**B** or **Escape** and the sample asks whether you really want to quit; **A** or **Enter**
quits, and **B** or **Escape** goes back.

The sample copies its content beside the executable when it builds, so it runs from any folder.

## What you are looking at

The sample is about 760 lines, its tests included, and most of them are comments explaining the
line below. Three parts are worth knowing before you copy it in the next step.

**`main.cpp` makes the decisions only a game can make**: the window's title and size, where the
content is, and which state runs first. Everything else is the engine's.

<SourceFile path="samples/minimal/main.cpp" from="ApplicationOptions options;" to="return app.run(" />

**A state is a screen or mode of the game.** The engine calls a state's `init()` once, then its
`update()` and `draw()` every frame. `HelloState` puts its two lines of text in a scene and
gives the scene one view covering the whole window:

<SourceFile
	path="samples/minimal/states/hello_state.cpp"
	from="this->scene_ = std::make_unique<Scene>(nullptr, nullptr);"
	to="this->scene_->add_view("
/>

**The question is a second state, pushed on top of the first.** `ConfirmState` knows nothing
about the screen below it. It hands back a `bool` when it closes, and `HelloState` decides what
the answer means. While the question is up, `HelloState` stops updating and dims its greeting,
and because the question does not cover the whole screen, the greeting stays visible underneath.

## The other sample

LineSweeper, the falling-block game, was built too. From the same `Labrador` folder:

```bat
out\build\x64-debug\samples\linesweeper\LineSweeperSample.exe
```

Escape pauses it; press Down until **QUIT** is chosen, then Enter, to quit. Once the board fills
and it says **TOPPED OUT**, Escape does nothing: press R to start a new match first.
[Examples](/examples/) lists its controls and the order in which to read its code, and
[Run the samples](/docs/guides/samples/) starts the other four. LineSweeper is there to be read,
though. The minimal sample is the one you copy, and the next step does that.
