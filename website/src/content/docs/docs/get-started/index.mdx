This path takes you from a Windows machine with nothing installed to a project of your own that
builds against Labrador, runs, and shows a change you made. It has five steps, and each page
ends where the next begins.

Labrador builds on Windows, and the game it builds runs on Windows and in a desktop browser
through WebGL2. This path builds for Windows; [Running them](/examples/#running-them) on the
Examples page says how a sample becomes a page instead.

There is no editor to install. A game is C++ you write in your own IDE, its content is JSON in a
text editor, and the tools that convert images and fonts run from the command line; if you were
looking for an editor, read [what Labrador is not](/#what-labrador-is-not) before installing
anything.

## What you need to know already

Some C++, and how to use a command prompt. The guide explains every command it asks you to
type, but it does not teach the language.

## What it was checked against

These pages were followed by hand on Windows 11 with Visual Studio's x64 Native Tools Command
Prompt on 4 October 2026, a run recorded in Labrador's commit `68b392d`: every command was run,
and the project in step 4 was built from the public repository as its page then described, with
four include edits where it now lists five. Some steps have changed since, and the folder advice
in step 1, its `subst` drive included, and the build in step 2 were checked by hand again on
13 October. The revision at the bottom of each page is the one the page
was built from, which can be later than any of these.

On 25 October 2026 steps 2 to 5 were followed again on a fast desktop that already had Visual
Studio 2026 and Git, from a fresh public clone and with vcpkg's caches empty, with steps 2 and 3 built at commit
`6be26c9` and step 4 at the `v0.1.0` tag: every command worked as written. From the clone to the project's own window
took about six minutes.

One part is checked on every change to Labrador. Its CI assembles the project in step 4 from the
files and edits that page gives, with the engine taken from the change itself rather than from
GitHub, builds it, and checks that the engine's tests stay out of it. That check does not run the
game, use Git, or do steps 1 to 3 and 5.

If a step does not do what the page says, that is a bug in the page:
[report it](https://github.com/matt439/Labrador/issues).
