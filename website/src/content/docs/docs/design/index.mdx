## How to read them

**They describe where the engine is going, not a status report.** They are written in the present
tense of the target. When code moves, it moves towards them. When a change contradicts one, either
the change is wrong or the document is, and the document is amended in the same commit, with the
reason.

**The trade-offs are vocabulary.** Each has a number, and the number stands for the whole
argument. "T3: take the simpler model" is a complete comment in a code review. Pages on this site
link those numbers to their entries in the philosophy.

**They were written for the people building the engine.** That makes them the deepest
explanation of why Labrador is the way it is, and not a tutorial. If you are new to the engine,
[Get started](/docs/get-started/) and [Why Labrador?](/why/) are the better first reads.
