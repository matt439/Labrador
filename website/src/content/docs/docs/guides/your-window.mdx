This page changes how the game from [Get the starter project](/docs/get-started/starter/) looks:
the greeting's colour, its size and where it starts, the size of the window, full screen, and
what is behind everything. Each part is a few lines in one or two files, and each ends with the
same build, test and run line. Do them in order or pick the ones you want: each section says
what it needs from the ones before. All of them together take about 30 minutes.

Before you start, do [Make a first change](/docs/get-started/first-change/), so that you know the
edit, build and run loop and have a copy of your game to go back to. Make a fresh copy now with
that page's step 1 line. The window's title is on that page too, in its step 4.

Every command runs in the x64 Native Tools Command Prompt, in your project's folder:

```bat
cd /d C:\dev\mygame
```

## The greeting's colour

<Steps>

1. **Open the greeting's code.**

   ```bat
   notepad game\states\hello_state.cpp
   ```

   Search with **Ctrl+F** for `this->greeting_ = this->scene_->add(`. These are the lines that
   make the greeting, and the last of them gives its colour. The second line has your
   greeting's own words, `Hello from my game.` after
   [Make a first change](/docs/get-started/first-change/)'s step 2, where the lines below show
   the starter's:

   <SourceFile
   	path="samples/minimal/states/hello_state.cpp"
   	from="this->greeting_ = this->scene_->add("
   	to="labrador::Colour::white));"
   	mark="labrador::Colour::white"
   />

   Change `white` to `orange`, so that the last line reads:

   ```cpp
   		labrador::Colour::orange));
   ```

2. **Change it where the greeting comes back.** While the quit question is open, the greeting is
   dimmed to grey, and when the question closes it is set back to white. Search for
   `void HelloState::on_resume()`:

   <SourceFile
   	path="samples/minimal/states/hello_state.cpp"
   	from="void HelloState::on_resume()"
   	to="this->greeting_->set_colour(labrador::Colour::white);"
   />

   Change `white` to `orange` here as well, so that the line reads as below, then save and close
   Notepad. Without this change the greeting starts orange and turns white the first time you
   answer the quit question with **Escape**.

   ```cpp
   	this->greeting_->set_colour(labrador::Colour::orange);
   ```

3. **Build, test and run.** Quit the game if it is open, then run the line from
   [Make a first change](/docs/get-started/first-change/)'s step 5:

   ```bat
   cmake --build --preset x64-debug && ctest --preset x64-debug && out\build\x64-debug\game\MyGame.exe
   ```

   Only `hello_state.cpp` is compiled again; on a fast desktop the line took 5 seconds before
   the game opened. It ends like this:

   ```text title="Output"
   [3/4] Building CXX object game\CMakeFiles\MyGame.dir\states\hello_state.cpp.obj
   [4/4] Linking CXX executable game\MyGame.exe
   Test project C:/dev/mygame/out/build/x64-debug
       Start 1: MyGameTests
   1/2 Test #1: MyGameTests ......................   Passed    0.01 sec
       Start 2: MyGameSmokeTests
   2/2 Test #2: MyGameSmokeTests .................   Passed    0.78 sec

   100% tests passed, 0 tests failed out of 2
   ```

   The greeting is orange. Press **Escape**: it turns grey under the yellow quit question. Press
   **Escape** again to say no, and it is orange again.

</Steps>

### The names you can use

`orange` is one of the 148 named colours the engine has, the colours web pages use, spelt in
lower case with `_` between words. Each is written `labrador::Colour::` and the name. This is
the whole list, from the engine's own header:

<SourceFile
	path="engine/render/colour.h"
	from="static const Colour alice_blue;"
	to="static const Colour yellow_green;"
	collapsed
/>

A few to try: `gold`, `tomato`, `deep_sky_blue`, `lime_green`, `hot_pink`, `light_gray`. Grey is
spelt both ways, `dark_gray` and `dark_grey`, and as on the web, `dark_gray` is lighter than
`gray`. The starter already uses three: the hint along the bottom is `dark_gray`, the touch
markers `gold`, and the quit question `goldenrod`.

### A colour of your own

Any colour can be made from its red, green and blue, each a whole number from 0 to 255, the
numbers a paint program shows. In place of `labrador::Colour::orange` in both places, write:

```cpp
labrador::Colour(255, 160, 40)
```

All three numbers must be whole numbers, or all three must have a point and an `f`, from `0.0f`
to `1.0f`, such as `labrador::Colour(1.0f, 0.63f, 0.16f)`. Mixing the two kinds is the
`C2440` error below. A fourth number is how see-through the colour is, but it does not blend the
way a paint program's does; [Sprites and text](/docs/guides/sprites-and-text/) explains how
colours blend.

### If the colour does not build

<Aside type="caution" title="hello_state.cpp(88): error C2039: 'orang': is not a member of 'labrador::Colour'">
The name after `Colour::` is not one of the names in the list. It is usually misspelt, or has
a capital: `Colour::Orange` gives the same error, naming `Orange`. A second line,
`error C2065: 'orang': undeclared identifier`, follows from the first. Copy the name from the
list above.
</Aside>

<Aside type="caution" title="hello_state.cpp(88): error C2440: '<function-style-cast>': cannot convert from 'initializer list' to 'labrador::Colour'">
The three numbers are of two kinds, here `labrador::Colour(255, 160, 40.5f)`. The notes under
it name the two ways the compiler could have read them, `Colour(int,int,int,int)` and
`Colour(float,float,float)`, and say it would not choose: `while trying to match the argument
list '(int, int, float)'`. Use three whole numbers, or three numbers with a point and an `f`.
</Aside>

## Bigger text

The greeting is drawn at the size of its font, 16 pixels high. The number after the colour
makes it bigger: `2.0f` draws it twice as big. Open the greeting's code again:

```bat
notepad game\states\hello_state.cpp
```

Search for `this->greeting_ = this->scene_->add(` as in step 1. At the last of its lines, the
one you changed to `orange`, add `, 2.0f` after the colour, so that it reads:

```cpp
		labrador::Colour::orange, 2.0f));
```

Save, close Notepad, and build, test and run with the line from step 3. The greeting is twice as wide and twice as high,
and grows to the right and down from where it was, because the position the game gives it is
its top-left corner. Drawn bigger than its font, its letters are blocky.
[Fonts and text in your game](/docs/guides/your-font/) makes a 32-point font for text that is
meant to be big.

## Where things start

The window is measured in pixels from its top-left corner: across to the right first, then down.
In the starter's 1280 by 720 window, `Vector2F(0.0f, 0.0f)` is the top-left corner,
`Vector2F(1280.0f, 720.0f)` the bottom-right, and `Vector2F(640.0f, 360.0f)` the middle. Open
the greeting's code:

```bat
notepad game\states\hello_state.cpp
```

In `init()`, search for `this->motion_.centre =`. It is the third of these four lines:

<SourceFile
	path="samples/minimal/states/hello_state.cpp"
	from="const Vector2F resolution ="
	to="resolution.y * 0.5f);"
/>

`resolution` is the window's size, so `resolution.x * 0.5f - 120.0f` is 120 pixels left of the
middle, and `resolution.y * 0.5f` is half-way down. That is the point the greeting circles. To
start it near the top-left corner instead, change the last two lines, the
`this->motion_.centre =` line and the one after it, to this one line, and leave the first two as
they are:

```cpp
	this->motion_.centre = Vector2F(200.0f, 150.0f);
```

Save, close Notepad, and build, test and run: the greeting circles near the top-left corner.
Changing the second and third lines instead leaves half of two lines behind, and the build stops
with `hello_state.cpp(77): error C2059: syntax error: ')'`: make the four lines the ones above
again, then change the last two.
The hint along the bottom is placed the same way, at `Vector2F(24.0f, resolution.y - 40.0f)`:
24 pixels from the left and 40 up from the bottom. Positions are written with `.0f` on each
number, the way the engine's own code writes them; `Vector2F(200, 150)` builds too.

## The window's size

The window's size is in `game\main.cpp`:

```bat
notepad game\main.cpp
```

Search for `options.resolution`:

<SourceFile path="samples/minimal/main.cpp" from="options.resolution" to="options.resolution" />

The size is one of four, the four the engine names:

<SourceFile path="engine/render/screen_resolution.h" from="s_1280_720," to="s_3840_2160," />

Change `s_1280_720` to `s_1920_1080`, save and close Notepad, and build, test and run with the
line from step 3. This time `main.cpp` is compiled again. The window is 1920 pixels wide and
1080 high inside its frame, and the hint has moved with it to the new bottom, because `init()`
places it from `resolution`. So does the greeting, unless you gave it a place of its own in the
section before: `Vector2F(200.0f, 150.0f)` stays where it is. The text stays the same size in
pixels, so it looks smaller.

**Choose a size smaller than your screen.** The window's frame and title bar take room too, so a
window as big as the screen does not fit. On a 2560 by 1440 screen, `s_2560_1440` gave a window
2576 by 1479 pixels with its frame, starting at the top-left corner, and its bottom 39 pixels
were off the bottom of the screen, under the taskbar. On a 1920 by 1080 laptop screen,
`s_1920_1080` does the same. A player can always drag the window's edge; what the game does then
is under [Full screen with F11](#full-screen-with-f11).

**In the browser** the page decides the size, not this line: the game draws into the page's
canvas, and its size is set in `game\web\shell.html`, where the canvas is as wide as the page,
up to 1280 pixels, and 16 by 9 in shape. `game\main_web.cpp` has the same `options.resolution`
line, but the canvas's size replaces it as soon as the page has laid the canvas out.

## Full screen from the start

Open `game\main.cpp` again:

```bat
notepad game\main.cpp
```

After the `options.resolution` line, whatever size it names, add one line, so that the two read,
here with the starter's size:

```cpp
		options.resolution = ScreenResolution::s_1280_720;
		options.fullscreen = true;
```

Save, close Notepad, and build, test and run. The test still passes: it runs the game hidden,
which is never full screen. Then the game fills the whole screen, with no frame or title bar.
`init()` reads the window's size when the game starts, which is now the size of your screen, so
the greeting circles the screen's middle and the hint is along its bottom, all at the same size
in pixels as before.

To leave it:

- **Escape**, then **Enter**, quits as before.
- **Alt+F4** closes the game at once, without the question.
- **Alt+Tab**, or the Windows key, switches to another window and leaves the game running behind
  it; click it on the taskbar to go back.

Delete the line again to go back to a window. The line is in `main.cpp`, so it changes the
Windows game only; `main_web.cpp` has no such line, and a page can go full screen only after the
player presses a key or clicks.

## Full screen with F11

This section lets the player switch with **F11** while the game runs, and keeps the game the same
shape at any size, with black bars at two sides when the screen is a different shape. It needs
four changes in `game\states\hello_state.cpp` and one in `game\states\confirm_state.cpp`, because
until now the game only looked at the window's size once, when it started. Before you start,
delete the `options.fullscreen = true;` line from the section above if you added it.

<Steps>

1. **Add the layout size and a function that fits it to the window.** Open the code:

   ```bat
   notepad game\states\hello_state.cpp
   ```

   Search for `touch_marker_offset =`. It is near the top, inside `namespace {`:

   <SourceFile
   	path="samples/minimal/states/hello_state.cpp"
   	from="const Vector2F touch_marker_offset"
   	to="const Vector2F touch_marker_offset"
   />

   Click at the end of that line, press **Enter** twice, and paste:

   ```cpp
   	// The size the game is laid out in, whatever size the window is.
   	const Vector2F layout_size = Vector2F(1280.0f, 720.0f);

   	// Gives the scene one view, the whole window, showing the layout as
   	// large as it fits, in the middle. A window of another shape has black
   	// bars at two of its sides.
   	void fit_view(Scene& scene, const ViewportManager& viewports)
   	{
   		const Viewport window = viewports.fullscreen_viewport();
   		scene.clear_views();
   		scene.add_view(window,
   			Camera::frame(RectangleF(Vector2F::zero, layout_size), window));
   	}
   ```

   A **view** is a rectangle of the window and a **camera** that says which part of the game it
   shows and how big. `Camera::frame` makes the camera that shows the 1280 by 720 the game is laid
   out in as large as the window allows: twice as big on a 2560 by 1440 screen.

2. **Lay the game out at that size, and fit the view.** In `init()`, search for
   `const Vector2F resolution =`. Change the two lines

   ```cpp
   	const Vector2F resolution =
   		this->app_->resolution_manager()->resolution_vec();
   ```

   to one line:

   ```cpp
   	const Vector2F resolution = layout_size;
   ```

   Everything in `init()` is placed from `resolution`, so the game is now always laid out at
   1280 by 720. Then search for `this->scene_->add_view(`, the last line of `init()`:

   <SourceFile
   	path="samples/minimal/states/hello_state.cpp"
   	from="this->scene_->add_view("
   	to="this->scene_->add_view("
   />

   Replace that line with:

   ```cpp
   	fit_view(*this->scene_, *this->app_->viewport_manager());
   ```

3. **Switch on F11, and fit the view on every frame.** In `update()`, search for
   `const Keyboard& keyboard =`, with the `=`: without it, the search first finds the
   `keyboard_direction` function near the top. Click at the end of that line, press **Enter**
   twice, and paste:

   ```cpp
   	if (keyboard.pressed(Key::f11))
   	{
   		this->app_->set_fullscreen(!this->app_->fullscreen());
   	}
   ```

   `!` means "not": F11 asks for full screen when the game is in a window, and for a window when
   it is full screen. Then go to the end of `update()`, the last line before
   `void HelloState::on_suspend()`:

   <SourceFile
   	path="samples/minimal/states/hello_state.cpp"
   	from="this->scene_->update(dt);"
   	to="this->scene_->end_tick();"
   />

   Click at the end of `this->scene_->end_tick();`, press **Enter** twice, and paste:

   ```cpp
   	fit_view(*this->scene_, *this->app_->viewport_manager());
   ```

   Without this line the window changes size and the view does not: after F11 the game is drawn
   in the top-left 1280 by 720 of the screen, with black around it.

4. **Keep the touch markers under the fingers.** Search for `marker->set_position(`. The lines
   are:

   <SourceFile
   	path="samples/minimal/states/hello_state.cpp"
   	from="marker->set_position(Vector2F("
   	to="touch_marker_offset);"
   />

   Replace those four lines with:

   ```cpp
   			const Scene::View& view = this->scene_->view(0);
   			marker->set_position(
   				view.camera.world_position(points[i].position, view.viewport) +
   				touch_marker_offset);
   ```

   A finger is reported in the window's pixels; `world_position` turns that into the game's
   1280 by 720 through the view's camera. Save and close Notepad.

5. **Lay the quit question out at the same size.** The question draws through the same camera,
   so it must be laid out at 1280 by 720 too, or full screen draws it off the screen:

   ```bat
   notepad game\states\confirm_state.cpp
   ```

   Search for `const Vector2F resolution =` and change its two lines, as in step 2, to:

   ```cpp
   	const Vector2F resolution = Vector2F(1280.0f, 720.0f);
   ```

   Save and close Notepad.

6. **Build, test and run** with the line from step 3 of the first section. It compiles
   `hello_state.cpp` and `confirm_state.cpp`, about 6 seconds in all. In a window the game looks
   as before. Press **F11**: the game fills the screen, drawn larger, everything where it was.
   **Escape** shows the question, larger too, in the same place. Press **Escape** to close it and
   **F11** to go back to a window. Drag the window's bottom edge down: the game stays 16 by 9,
   with black bars above and below it.

</Steps>

If the game was full screen from the start in the section before, it still works with these
changes: it is then laid out at 1280 by 720 and drawn larger, like after F11.

In the browser, the same build makes the game fit the canvas whatever the page's width.
Whether F11 there makes the canvas full screen was not checked: the browser's own F11 may take
the key first.

The line numbers in the messages below are those of a file with every section above done in
order; with a section skipped they are a line or two different, and the words are the same.

<Aside type="caution" title="hello_state.cpp(130): error C2065: 'keybaord': undeclared identifier">
A name in the pasted lines is misspelt, here `keyboard`, or the F11 lines were pasted above the
`const Keyboard& keyboard =` line, before `keyboard` exists. Paste them after it.
</Aside>

<Aside type="caution" title="hello_state.cpp(90): error C2143: syntax error: missing ';' before 'this'">
The line before the one named has lost its `;`: here `const Vector2F resolution = layout_size`
from step 2. The error names the line after, where the compiler noticed.
</Aside>

## A colour behind everything

The engine clears the window to black before each frame, and has no setting for another colour.
A background is something drawn first, because whatever is drawn later is drawn over it. This
section makes a small class that draws one rectangle of colour, and adds it to the scene before
anything else. It works with or without the sections above.

<Steps>

1. **Make the class.** It is one file, a header:

   ```bat
   if not exist game\states\backdrop.h type nul > game\states\backdrop.h
   notepad game\states\backdrop.h
   ```

   The first line makes an empty file and prints nothing. Paste all of this into it, then save and
   close Notepad:

   ```cpp title="game\states\backdrop.h"
   #pragma once

   #include "engine/core/game_object.h"
   #include "engine/math/rectanglef.h"
   #include "engine/math/rectanglei.h"
   #include "engine/math/vector2f.h"
   #include "engine/render/colour.h"
   #include "engine/render/render_resources.h"
   #include "engine/render/renderer.h"
   #include "engine/render/resource_factory.h"

   // A rectangle of one colour. Added to the scene before everything else, it is
   // drawn first, so it is the background behind the rest.
   class Backdrop : public labrador::GameObject
   {
   public:
   	Backdrop(const labrador::RectangleF& area, const labrador::Colour& colour,
   		const labrador::RenderResources& resources) :
   		texture_(resources.resolve_texture(labrador::white_texture_name)),
   		area_(area), colour_(colour)
   	{
   	}

   	void set_colour(const labrador::Colour& colour)
   	{
   		this->colour_ = colour;
   	}

   	void update(float /*dt*/) override
   	{
   	}

   	void draw(labrador::DrawList& draw_list) const override
   	{
   		// The engine's white texture is one white pixel; drawn over the
   		// whole area and tinted, it is a rectangle of that colour.
   		draw_list.draw_sprite(this->texture_,
   			labrador::RectangleI(0, 0, 1, 1), this->area_, this->colour_,
   			0.0f, labrador::Vector2F::zero, labrador::SpriteFlip::none, 0.0f);
   	}

   	labrador::RectangleF bounds() const override
   	{
   		return this->area_;
   	}

   private:
   	labrador::TextureHandle texture_;
   	labrador::RectangleF area_;
   	labrador::Colour colour_;
   };
   ```

   The engine always has a texture one white pixel across, named by `white_texture_name`. `draw`
   stretches it over the whole rectangle and tints it with the colour, which is how every solid
   rectangle is drawn on this engine. The whole class is in the header, so
   `game\CMakeLists.txt` does not need to list it.

2. **Add it to the scene first.** Open the state's code:

   ```bat
   notepad game\states\hello_state.cpp
   ```

   Search for `game/states/confirm_state.h` and add a line before it, so the two read:

   ```cpp
   #include "game/states/backdrop.h"
   #include "game/states/confirm_state.h"
   ```

   Then search for `this->greeting_ = this->scene_->add(`. Click at the start of that line and
   paste these lines above it, with an empty line after them:

   ```cpp
   	this->scene_->add(std::make_unique<Backdrop>(
   		RectangleF(Vector2F::zero, resolution), labrador::Colour::midnight_blue,
   		*resources));
   ```

   `RectangleF(Vector2F::zero, resolution)` is the rectangle from the top-left corner the size of
   the window. Any colour from [the list](#the-names-you-can-use) works in place of
   `midnight_blue`. Save and close Notepad.

3. **Build, test and run** with the line from the first section. It compiles `hello_state.cpp`,
   about 6 seconds. The window is dark blue behind the greeting and the hint, and the quit
   question draws over it too.

</Steps>

**The order is what matters.** Things in the scene are drawn in the order they were added, each
over the ones before. Added after the greeting, the rectangle covers it: the window shows dark
blue and the hint, which was added later, and no greeting. If the greeting disappears, move the
three lines above `this->greeting_ = this->scene_->add(`.

If you did [Full screen with F11](#full-screen-with-f11), the rectangle is 1280 by 720 like the
rest of the layout and is drawn larger with it; the bars at the sides of a window of another
shape stay black, because they are outside it.

<Aside type="caution" title="hello_state.cpp(98): error C2065: 'Backdrop': undeclared identifier">
`hello_state.cpp` does not include the class: the `#include "game/states/backdrop.h"` line is
missing or misspelt. Two `C2672` lines, about `std::make_unique` and `labrador::Scene::add`,
follow from it. Add the line as in step 2. The line is 98 after every section above; in a game
with only this section, it is 86.
</Aside>

<Aside type="caution" title="memory(3666): error C2665: 'Backdrop::Backdrop': no overloaded function could convert all the argument types">
The error starts in a file of Visual Studio's own, `memory`, which is where `std::make_unique`
is. The notes under it say what is wrong: `cannot convert argument 3 from
'labrador::RenderResources *' to 'const labrador::RenderResources &'`. The `*` before `resources`
in the pasted lines is missing. `resources` is a pointer, and `*resources` is the thing it points
at, which is what the class takes.
</Aside>

## A picture behind everything

A picture is a background the same way: drawn first. This needs
[Put a picture in your game](/docs/guides/your-picture/) done first, which sets up the textures
folder and the `Picture` class, and [Install the content tools](/docs/guides/content-tools/).

1. **Make a picture the size of the window.** It must be 1280 by 720 pixels. To try it with one
   drawn for you, this line draws an evening sky with green ground along the bottom, as
   `sky.png` in your project's folder:

   ```bat
   powershell -NoProfile -Command "Add-Type -AssemblyName System.Drawing; $b = New-Object Drawing.Bitmap 1280,720; $g = [Drawing.Graphics]::FromImage($b); $r = New-Object Drawing.Rectangle 0,0,1280,720; $s = New-Object Drawing.Drawing2D.LinearGradientBrush $r, ([Drawing.Color]::MidnightBlue), ([Drawing.Color]::DarkOrange), 90; $g.FillRectangle($s, $r); $g.FillRectangle([Drawing.Brushes]::DarkGreen, 0, 600, 1280, 120); $b.Save('sky.png'); $s.Dispose(); $g.Dispose(); $b.Dispose()"
   ```

   It prints nothing. Then convert it as the picture page's step 2 does:

   ```bat
   C:\dev\tools\texconv.exe -f R8G8B8A8_UNORM -m 1 -pmalpha --ignore-srgb -y -o game\content\textures sky.png
   ```

   It ends `reading sky.png (1280x720 B8G8R8A8_UNORM 2D) as (1280x720 R8G8B8A8_UNORM 2D a:Opaque)`
   and `writing game\content\textures\sky.dds`.

2. **List it.** In `game\content\manifest.json`, the `texture` group's names become:

   ```json
               "names": [
                   "hero",
                   "sky"
               ]
   ```

   with a comma after `"hero"`. In `game\CMakeLists.txt`, after the line ending
   `content/textures/hero.dds"` that the picture page added, add the same line for the sky, so
   that the browser build packages the page again when it changes:

   ```cmake
           "${CMAKE_CURRENT_SOURCE_DIR}/content/textures/hero.dds"
           "${CMAKE_CURRENT_SOURCE_DIR}/content/textures/sky.dds"
   ```

3. **Draw it first.** In `game\states\hello_state.cpp`, add these lines above
   `this->greeting_ = this->scene_->add(`, in place of the `Backdrop` lines if you added them:

   ```cpp
   	this->scene_->add(std::make_unique<Picture>(
   		"sky", 1280, 720, Vector2F::zero, *resources));
   ```

   `"sky"` is the name in the manifest, `1280, 720` its size, and `Vector2F::zero` puts its
   top-left corner in the window's.

4. **Build, test and run.** The build runs CMake again, as on the picture page, and took 8
   seconds. The sky is behind the greeting, and the green ground behind the hint.

A misspelt name in the manifest or the code fails the start-up test with the messages listed on
[Put a picture in your game](/docs/guides/your-picture/#if-something-fails).
