This page makes the game from [Get the starter project](/docs/get-started/starter/) remember
where the player left the greeting. Pressing **Space** saves the point the greeting circles to
a small file in the player's own folder, and the next time the game starts, it starts there. It
adds two files of your own, `game\settings.h` and `game\settings.cpp`, lists the new `.cpp` in
`game\CMakeLists.txt`, and changes a few lines in `HelloState`. Then it opens the file, changes
it by hand, breaks it on purpose to see the message, and deletes it to start again. It takes
about 15 minutes.

Before you start:

- Do [Make a first change](/docs/get-started/first-change/), so that you know the edit, build
  and run loop and have a copy of your game to go back to. Make a fresh copy now with that
  page's step 1 line.

This page does not depend on the picture, animation or font pages, and works whether or not you
have done them. Every command runs in the x64 Native Tools Command Prompt, in your project's
folder:

```bat
cd /d C:\dev\mygame
```

<Steps>

1. **Make the settings header.** A header says what a `.cpp` file offers, so that other files
   can use it. First make the empty file, then open it:

   ```bat
   if not exist game\settings.h type nul > game\settings.h
   notepad game\settings.h
   ```

   The first line makes an empty file and prints nothing; it leaves the file alone if it is
   already there. Notepad opens the empty file. Paste all of this into it, then save and close
   Notepad:

   ```cpp title="game\settings.h"
   #pragma once

   #include "engine/math/vector2f.h"

   #include <filesystem>

   // What the game keeps from one run to the next. It is written to
   // settings.json, in the folder settings_directory() names.
   struct Settings
   {
   	// The point the greeting circles.
   	labrador::Vector2F greeting_centre = { 0.0f, 0.0f };
   };

   // The folder the settings file goes in: %LOCALAPPDATA%\MyGame on Windows,
   // and /save in a browser, where it lasts until the page is reloaded.
   std::filesystem::path settings_directory();

   // Writes settings.json in directory, making the folder first if it is not
   // there. Throws if the file cannot be written.
   void write_settings(const std::filesystem::path& directory,
   	const Settings& settings);

   // Reads settings.json from directory. Returns defaults when there is no
   // file, and throws, naming the file, when the file is there but wrong.
   Settings read_settings(const std::filesystem::path& directory,
   	const Settings& defaults);
   ```

   `Settings` holds what the game saves, one position for now. The three functions below it
   find the folder, write the file and read it. The file goes straight in `game`, beside
   `main.cpp`, because it is not a screen of the game: so it is `game\settings.h`, and other
   files include it as `"game/settings.h"`.

2. **Make the settings code.** Make the second file and open it the same way:

   ```bat
   if not exist game\settings.cpp type nul > game\settings.cpp
   notepad game\settings.cpp
   ```

   Paste all of this into it, then save and close Notepad:

   ```cpp title="game\settings.cpp"
   #include "game/settings.h"

   #include "engine/assets/json.h"
   #include "engine/render/text_encoding.h"

   #include <exception>
   #include <fstream>
   #include <memory>
   #include <stdexcept>
   #include <string>

   #if !defined(__EMSCRIPTEN__)
   #include <windows.h>
   #include <shlobj.h>
   #endif

   using namespace labrador;

   namespace
   {
   	// The shape of the file this game writes. A later version of the game
   	// that stores something else writes 2, and can still tell a 1 apart.
   	constexpr int settings_version = 1;
   }

   std::filesystem::path settings_directory()
   {
   #if defined(__EMSCRIPTEN__)
   	return "/save";
   #else
   	wchar_t* raw = nullptr;
   	if (FAILED(SHGetKnownFolderPath(FOLDERID_LocalAppData, KF_FLAG_CREATE,
   		nullptr, &raw)))
   	{
   		throw std::runtime_error("Cannot find this user's LocalAppData folder");
   	}

   	// Windows made the text, and it must be given back to Windows.
   	struct FolderDeleter
   	{
   		void operator()(wchar_t* value) const
   		{
   			CoTaskMemFree(value);
   		}
   	};
   	const std::unique_ptr<wchar_t, FolderDeleter> folder(raw);
   	return std::filesystem::path(folder.get()) / L"MyGame";
   #endif
   }

   void write_settings(const std::filesystem::path& directory,
   	const Settings& settings)
   {
   	std::filesystem::create_directories(directory);
   	std::ofstream output(directory / "settings.json",
   		std::ios::binary | std::ios::trunc);
   	output.exceptions(std::ios::failbit | std::ios::badbit);
   	output << "{\n"
   		<< "    \"version\": " << settings_version << ",\n"
   		<< "    \"greeting_x\": " << settings.greeting_centre.x << ",\n"
   		<< "    \"greeting_y\": " << settings.greeting_centre.y << "\n"
   		<< "}\n";
   	output.close();
   }

   Settings read_settings(const std::filesystem::path& directory,
   	const Settings& defaults)
   {
   	const std::filesystem::path path = directory / "settings.json";
   	if (!std::filesystem::exists(path))
   	{
   		return defaults;
   	}

   	const std::string name = narrow(path.wstring());
   	try
   	{
   		const JsonDocument document = read_json_file(name.c_str());
   		const JsonValue root = document.root();
   		if (root.integer("version") != settings_version)
   		{
   			throw std::runtime_error("'" + name + "' has version " +
   				std::to_string(root.integer("version")) +
   				", and this game reads version " +
   				std::to_string(settings_version));
   		}

   		Settings settings;
   		settings.greeting_centre = Vector2F(root.number("greeting_x"),
   			root.number("greeting_y"));
   		return settings;
   	}
   	catch (const std::exception& error)
   	{
   		throw std::runtime_error(std::string(error.what()) +
   			". Correct the file, or delete it to start from the defaults.");
   	}
   }
   ```

   What each part does:

   - **`settings_directory`** asks Windows for the player's **LocalAppData** folder, such as
     `C:\Users\you\AppData\Local`, and adds `MyGame` to it. A game must not save beside its
     `.exe`: an installed game can be in a folder nobody may write to. `SHGetKnownFolderPath`
     hands back text that Windows owns, and `CoTaskMemFree` gives it back; the small
     `FolderDeleter` does that whatever happens. Replace `MyGame` with your game's name if you
     like, and then keep it: a different name is a different folder, and the old file is left
     behind. In a browser there is no such folder, and the lines under `#if defined(__EMSCRIPTEN__)`
     use `/save` instead; [In the browser build](#in-the-browser-build) says what that means.
   - **`write_settings`** makes the folder if it is not there, opens `settings.json`, and writes
     it a line at a time. `output.exceptions(...)` makes a failed write throw, rather than fail
     quietly, so the game can tell the player that the save did not happen.
   - **`read_settings`** returns the defaults it is given when there is no file: the first time
     the game runs, or after you delete the file. Otherwise it reads the file with the engine's
     `read_json_file`, checks that `version` is `1`, and reads the two numbers. Every one of those
     reads stops with a message that names the file and what is wrong with it, and the `catch`
     adds what to do about it. It never replaces a file it cannot read, because that file may be
     the only copy of what the player saved.

   The engine reads JSON but does not write it, so `write_settings` writes the text itself.
   That is fine for a few numbers. [Settings and saves](/docs/guides/settings-and-saves/) says
   more about the choices here.

   <Aside type="caution" title="Do not copy the save check's whole file">
   [Settings and saves](/docs/guides/settings-and-saves/) shows parts of
   <RepoLink path="tools/save_check/settings.cpp">tools/save_check/settings.cpp</RepoLink>, the
   engine's own check of this code. That file has an `int main()` of its own at the bottom, for
   the browser. Your game already has one in `main_web.cpp`, so a copy of the whole file stops
   the browser build with `wasm-ld: error: duplicate symbol: __original_main`, then the same
   for `main` and `__main_void`. Its functions also take a
   volume rather than a `Settings`, so they do not match the header above. Use the file above.
   </Aside>

3. **List settings.cpp in the build, twice.** Every `.cpp` file in your game is listed by name
   in `game\CMakeLists.txt`, and a file that is not listed is not compiled. The game's own files
   are listed **twice**: once for the [browser build](/docs/guides/browser/), and once for
   Windows. A file missing from one list breaks only that build, so add it to both now, even if
   you never build for the browser. Open the build file:

   ```bat
   notepad game\CMakeLists.txt
   ```

   First, search with **Ctrl+F** for `main_web.cpp`. The first match is in the comment
   `# The browser build: main_web.cpp in place of main.cpp`; press **Enter** in the search box (or
   **F3**) to go to the next one. You are now in the browser's list, near the top:

   ```cmake
       add_executable(MyGame
           main_web.cpp
           states/confirm_state.cpp
           states/hello_state.cpp
       )
   ```

   Add a line after `main_web.cpp`, with the same spaces in front of it, so the list reads:

   ```cmake
       add_executable(MyGame
           main_web.cpp
           settings.cpp
           states/confirm_state.cpp
           states/hello_state.cpp
       )
   ```

   Next, search for `add_executable(MyGame WIN32`. This is the Windows list, with the libraries
   the game links just below it:

   ```cmake
   add_executable(MyGame WIN32
       main.cpp
       states/confirm_state.cpp
       states/hello_state.cpp
       dpi_aware.manifest
   )
   target_link_libraries(MyGame PRIVATE
       MyGameRules
       LabradorEngine
       labrador_settings
   )
   ```

   Add `settings.cpp` after `main.cpp`, and `shell32` and `ole32` after `labrador_settings`, so
   the lines read:

   ```cmake
   add_executable(MyGame WIN32
       main.cpp
       settings.cpp
       states/confirm_state.cpp
       states/hello_state.cpp
       dpi_aware.manifest
   )
   target_link_libraries(MyGame PRIVATE
       MyGameRules
       LabradorEngine
       labrador_settings
       shell32
       ole32
   )
   ```

   `shell32` and `ole32` are the Windows libraries that `SHGetKnownFolderPath` and
   `CoTaskMemFree` come from. They go only in this Windows half: the browser has neither. The
   names `settings.cpp` are written from the `game` folder, because that is where this build
   file is. Save and close Notepad.

4. **Make room for a status line.** Open the header of the state that runs the starter's screen:

   ```bat
   notepad game\states\hello_state.h
   ```

   Search for `hint_ = nullptr;` and add a line after it, so the two read:

   ```cpp
   	labrador::Label* hint_ = nullptr;
   	labrador::Label* status_ = nullptr;
   ```

   `status_` is a line of text that will say `Saved.`, or why a save failed. If another page
   has already added a line after `hint_`, add this one after that. Save and close Notepad.

5. **Load the settings when the game starts.** Open the state's code:

   ```bat
   notepad game\states\hello_state.cpp
   ```

   It needs three more `#include` lines. Search for `engine/math/vector2f.h` and add a line after
   it, so the two read:

   ```cpp
   #include "engine/math/vector2f.h"
   #include "engine/render/text_encoding.h"
   ```

   If `engine/render/text_encoding.h` is there already, from
   [Fonts and text in your game](/docs/guides/your-font/), leave it and do not add a second one.
   Then search for `game/states/confirm_state.h` and add a line above it, so the two read:

   ```cpp
   #include "game/settings.h"
   #include "game/states/confirm_state.h"
   ```

   Then search for `#include <cstddef>` and add a line after it, so the two read:

   ```cpp
   #include <cstddef>
   #include <exception>
   ```

   Now search for `resolution.y * 0.5f);`. These lines, at the start of `init()`, put the
   greeting in the middle of the window:

   <SourceFile
   	path="samples/minimal/states/hello_state.cpp"
   	from="this->motion_.centre = Vector2F("
   	to="resolution.y * 0.5f);"
   />

   Click at the end of the second line, after the `;`, press **Enter**, and paste these lines:

   ```cpp

   	// Start where the player saved, or in the middle if nothing is saved.
   	Settings defaults;
   	defaults.greeting_centre = this->motion_.centre;
   	const Settings settings = read_settings(settings_directory(), defaults);
   	this->motion_.centre = settings.greeting_centre;
   ```

   The middle of the window becomes the default, and what `read_settings` returns replaces it:
   the saved point if there is a file, the middle if there is not. If the file is broken,
   `read_settings` throws, and the game stops at start-up with the message, as
   [How errors show](#how-errors-show) describes.

6. **Add the status line.** In the same file, search for `this->hint_ = this->scene_->add(`.
   Click at the start of that line and paste these lines above it, with an empty line after
   them:

   ```cpp
   	this->status_ = this->scene_->add(std::make_unique<Label>(
   		L"Space saves where the greeting is.", font_name,
   		Vector2F(24.0f, resolution.y - 70.0f), resources,
   		labrador::Colour::dark_gray));
   ```

   This is a `Label` like the hint, in the same grey, 30 pixels above it.

7. **Save when the player presses Space.** In the same file, search for
   `this->motion_ = step_motion(`. These lines, in `update()`, move the greeting on each step:

   <SourceFile
   	path="samples/minimal/states/hello_state.cpp"
   	from="this->motion_ = step_motion(this->motion_,"
   	to="keyboard_direction(keyboard), dt);"
   />

   Click at the start of the first of them and paste these lines above it, with an empty line
   after them:

   ```cpp
   	// Space saves the point the greeting circles, for the next start.
   	if (keyboard.pressed(Key::space))
   	{
   		try
   		{
   			Settings settings;
   			settings.greeting_centre = this->motion_.centre;
   			write_settings(settings_directory(), settings);
   			this->status_->set_text(L"Saved.");
   		}
   		catch (const std::exception& error)
   		{
   			this->status_->set_text(L"Could not save: " + widen(error.what()));
   		}
   	}
   ```

   `keyboard.pressed(Key::space)` is true on the one step on which Space goes down, so holding
   it saves once. `try` runs the save, and if anything in it throws, `catch` puts the reason on
   the status line instead of `Saved.`, and the game goes on. `widen` turns the reason into the
   wide text a `Label` draws. Space is free in the starter: the arrows and **W**, **A**, **S** and
   **D** move the greeting, and Escape asks to quit. A function key such as **F5**, the usual
   quick-save key, would work on Windows, but a browser keeps the function keys for itself, and
   F5 reloads the page. Save and close Notepad.

8. **Build, test and run.** Quit the game if it is open, then run the line from
   [Make a first change](/docs/get-started/first-change/)'s step 5:

   ```bat
   cmake --build --preset x64-debug && ctest --preset x64-debug && out\build\x64-debug\game\MyGame.exe
   ```

   The build first runs CMake again, because `game\CMakeLists.txt` changed. That prints
   `[0/1] Re-running CMake...` and about 30 lines from vcpkg and CMake, including a list of
   packages and lines such as `find_package(doctest CONFIG REQUIRED)`; they are expected, not
   errors. Then it compiles `settings.cpp` for the first time, and the two files that include
   `hello_state.h`. On a fast desktop the whole line took 5 seconds before the game opened. It
   ends like this:

   ```text title="Output"
   -- Build files have been written to: C:/dev/mygame/out/build/x64-debug
   [1/7] Running utility command for game_content
   [2/7] Checking that no engine file includes a game header
   [3/7] Building CXX object game\CMakeFiles\MyGame.dir\main.cpp.obj
   [4/7] Building CXX object game\CMakeFiles\MyGame.dir\states\hello_state.cpp.obj
   [5/7] Building CXX object game\CMakeFiles\MyGame.dir\settings.cpp.obj
   [6/7] Linking CXX executable game\MyGame.exe
   Test project C:/dev/mygame/out/build/x64-debug
       Start 1: MyGameTests
   1/2 Test #1: MyGameTests ......................   Passed    0.01 sec
       Start 2: MyGameSmokeTests
   2/2 Test #2: MyGameSmokeTests .................   Passed    0.68 sec

   100% tests passed, 0 tests failed out of 2
   ```

   Then the game opens, with the greeting in the middle, because nothing is saved yet. Above the
   controls hint, a new grey line says `Space saves where the greeting is.`

9. **Save, and start again.** Move the greeting with the arrow keys or WASD, up and to the left
   for example, and press **Space**. The grey line changes to `Saved.` Quit the game: **Escape**,
   then **Enter**. Start it again:

   ```bat
   out\build\x64-debug\game\MyGame.exe
   ```

   The greeting starts where you left it, still circling, and the grey line says
   `Space saves where the greeting is.` again. Quit it before you go on.

</Steps>

## Look at the file

The game wrote `settings.json` in your LocalAppData folder. `%LOCALAPPDATA%` is that folder's
name in the prompt, so `type` can show the file without your having to know where it is:

```bat
type "%LOCALAPPDATA%\MyGame\settings.json"
```

```text title="Output"
{
    "version": 1,
    "greeting_x": 313.335,
    "greeting_y": 160.001
}
```

Your numbers depend on where you left the greeting. They are pixels from the window's left edge
and from its top: the window is 1280 wide and 720 high. The greeting starts at `520`, `360`:
halfway down, and 120 pixels left of halfway across (640), so that the text, which starts at the
point and runs to the right, looks centred. The point is the one the greeting circles, not the corner of its text.
To see the whole path, run `echo %LOCALAPPDATA%\MyGame`; it prints a path such as
`C:\Users\you\AppData\Local\MyGame`, with your Windows user name.

## Change it by hand

Open the file in Notepad:

```bat
notepad "%LOCALAPPDATA%\MyGame\settings.json"
```

Change the two numbers, keeping the comma after the first and the quotation marks round the
names, so the file reads:

```json title="%LOCALAPPDATA%\MyGame\settings.json"
{
    "version": 1,
    "greeting_x": 900,
    "greeting_y": 500
}
```

Save and close Notepad, then start the game with the line from step 9. It starts with the greeting
in the lower right of the window, without a rebuild: the game reads the file each time it
starts. A whole number such as `900` is read the same as `900.0`.

## Start again from the defaults

Delete the file:

```bat
del "%LOCALAPPDATA%\MyGame\settings.json"
```

It prints nothing. The next time the game starts, there is no file, so `read_settings` returns
the defaults, and the greeting starts in the middle. If `del` prints
`Could Not Find C:\Users\...\MyGame\settings.json`, there was no file to delete: nothing had been
saved, or it was deleted already. After the delete, `type` on the file prints
`The system cannot find the file specified.`

## How errors show

A mistake in this page's work shows in one of four places:

- **The build stops** with an `error` line: a slip in the C++ code or a file missing from a list
  in `game\CMakeLists.txt`. [Read a build error](/docs/get-started/build-errors/) shows how to
  find the line that matters, and the link errors are below.
- **The start-up test fails** because `settings.json` is there but wrong. The game reads the
  file in `init()`, and so does the start-up test, which runs the game hidden on your computer
  with your file. The `ctest` output shows `***Failed` for `MyGameSmokeTests` and, under it, a
  line starting `startup failure:` that names the file and says what is wrong:

  ```text title="Output"
  2/2 Test #2: MyGameSmokeTests .................***Failed    0.24 sec
  startup failure: read_json_file - 'C:\Users\...\MyGame\settings.json' is not valid JSON: Missing a comma or '}' after an object member. (offset 46). Correct the file, or delete it to start from the defaults.

  50% tests passed, 1 tests failed out of 2
  ```

  Started on its own, the game shows the message, without `startup failure:` in front, in a box
  titled `Sample - startup failure`, and closes when you click **OK**. Correct the file, or delete it as
  in [Start again from the defaults](#start-again-from-the-defaults).
- **The status line says `Could not save:`** and a reason, when you press Space and the file
  cannot be written. The game goes on. When the file could not be opened, as in the message
  below, the old file, if there is one, is as it was.
- **The browser build stops** with `wasm-ld: error`, when `settings.cpp` is in the Windows list
  but not the browser's. The Windows build works, so this shows only when you build for the
  browser.

Each message is below.

## If something fails

<Aside type="caution" title='hello_state.cpp.obj : error LNK2019: unresolved external symbol "class std::filesystem::path __cdecl settings_directory(void)" ...'>
`settings.cpp` is not in the Windows list, so its code was never compiled, and the linker found
no body for the functions `HelloState` calls. After `FAILED:` come two very long lines, the link
command and `LINK Pass 1: command ... failed (exit code 1120) with the following output:`, which
can be skipped. Then there is one `LNK2019` line for each function, and a count:

```text title="Output"
[3/4] Linking CXX executable game\MyGame.exe
FAILED: [code=4294967295] game/MyGame.exe
...
hello_state.cpp.obj : error LNK2019: unresolved external symbol "class std::filesystem::path __cdecl settings_directory(void)" (?settings_directory@@YA?AVpath@filesystem@std@@XZ) referenced in function "public: virtual void __cdecl HelloState::init(void)" (?init@HelloState@@UEAAXXZ)
hello_state.cpp.obj : error LNK2019: unresolved external symbol "void __cdecl write_settings(class std::filesystem::path const &,struct Settings const &)" (?write_settings@@YAXAEBVpath@filesystem@std@@AEBUSettings@@@Z) referenced in function "public: virtual void __cdecl HelloState::update(float)" (?update@HelloState@@UEAAXM@Z)
hello_state.cpp.obj : error LNK2019: unresolved external symbol "struct Settings __cdecl read_settings(class std::filesystem::path const &,struct Settings const &)" (?read_settings@@YA?AUSettings@@AEBVpath@filesystem@std@@AEBU1@@Z) referenced in function "public: virtual void __cdecl HelloState::init(void)" (?init@HelloState@@UEAAXXZ)
game\MyGame.exe : fatal error LNK1120: 3 unresolved externals
ninja: build stopped: subcommand failed.
```

Add `settings.cpp` after `main.cpp` in `add_executable(MyGame WIN32`, as in step 3, save, and run
the build line again; it reads the changed list by itself. If the file is in the list, check that
`dir game\settings.cpp` finds it, and that its functions are spelt as in step 2.
[Troubleshooting](/docs/troubleshooting/#lnk2019-unresolved-external-symbol) has more on this
error.
</Aside>

<Aside type="caution" title="wasm-ld: error: game/CMakeFiles/MyGame.dir/states/hello_state.cpp.o: undefined symbol: settings_directory()">
The browser build's form of the same thing: `settings.cpp` is in the Windows list but not in the
`add_executable(MyGame` inside `if(EMSCRIPTEN)`. It names each missing function, then `em++`
prints a very long line that ends `failed (returned 1)`, which can be skipped:

```text title="Output"
wasm-ld: error: game/CMakeFiles/MyGame.dir/states/hello_state.cpp.o: undefined symbol: settings_directory()
wasm-ld: error: game/CMakeFiles/MyGame.dir/states/hello_state.cpp.o: undefined symbol: read_settings(std::__2::filesystem::path const&, Settings const&)
wasm-ld: error: game/CMakeFiles/MyGame.dir/states/hello_state.cpp.o: undefined symbol: settings_directory()
wasm-ld: error: game/CMakeFiles/MyGame.dir/states/hello_state.cpp.o: undefined symbol: write_settings(std::__2::filesystem::path const&, Settings const&)
```

Add `settings.cpp` after `main_web.cpp`, as in step 3, and build again.
[Troubleshooting](/docs/troubleshooting/#wasm-ld-error--undefined-symbol) has more on it.
</Aside>

<Aside type="caution" title="startup failure: read_json_file - '...\MyGame\settings.json' is not valid JSON: Missing a comma or '}' after an object member. (offset 46). ...">
The file's punctuation is wrong: here the comma after `"greeting_x": 900` was deleted. The number
after `offset` counts characters from the start of the file to where the reader gave up, which is
just after the mistake. Open the file as in [Change it by hand](#change-it-by-hand) and compare it
with the one there, or delete it.
</Aside>

<Aside type="caution" title="startup failure: '...\MyGame\settings.json' has version 2, and this game reads version 1. ...">
The file's `version` is not `1`. This game wrote only version 1, so the file was changed by hand,
or written by another version of the game. Change it back to `1`, or delete the file.
</Aside>

<Aside type="caution" title="startup failure: '...\MyGame\settings.json': the document has no 'greeting_y'. ...">
A name the game reads is missing from the file, or misspelt there. The names must be spelt
exactly as the game writes them: `version`, `greeting_x` and `greeting_y`.
</Aside>

<Aside type="caution" title="startup failure: '...\MyGame\settings.json': greeting_x is not a number. ...">
A value has quotation marks round it, `"900"`, which makes it text. Numbers in JSON are written
without them: `900`.
</Aside>

<Aside type="caution" title="Could not save: ios_base::failbit set: iostream stream error">
On the status line, after Space: the file could not be opened for writing. This message came
from a `settings.json` marked read-only, with `attrib +r`; a file open in a program that locks it,
or a folder you may not write to, gives the same. To clear the read-only mark:

```bat
attrib -r "%LOCALAPPDATA%\MyGame\settings.json"
```

It prints nothing. Then press Space again.
</Aside>

**The greeting starts in the middle after you saved.** The game read no file. Check with the
`type` line in [Look at the file](#look-at-the-file). If the file is there, the build may not have
the code that reads it: run the build line from step 8 and read its last lines for an `error`.

**Space does nothing.** The game window must have the keyboard: click it first. If it still does
nothing, check the lines from step 7 against the page, and that the build worked.

**Leaving out `shell32` and `ole32`.** With the starter, the build still works without the two
library names from step 3, because CMake passes both to Visual Studio's linker for every program
anyway. Keep them: they say what `settings.cpp` needs, and do not depend on that default.

## In the browser build

With `settings.cpp` in both lists, the [browser build](/docs/guides/browser/) compiles and runs
the same code, and Space saves there too. A page has no LocalAppData folder:
`settings_directory()` returns `/save`, a folder in the page's own memory, and the file written
there is read back if the game reads it again while the page is open. Reloading the page or
closing it loses it, and the game starts in the middle again. `shell32` and `ole32` are only in
the Windows half of `game\CMakeLists.txt`, so the browser build does not look for them.

To keep the file after a reload, the page must copy `/save` to the browser's own storage and
back. [Settings and saves](/docs/guides/settings-and-saves/#restore-browser-storage-before-starting-the-game)
shows how, with a small JavaScript file and two link options.

## Where to go next

- [Settings and saves](/docs/guides/settings-and-saves/) applies settings such as full screen and
  volume to the running game, and keeps browser saves after a reload.
- [Read a build error](/docs/get-started/build-errors/) has more on the messages a build gives.
- [Build for the browser](/docs/guides/browser/) builds the same game as a web page.

To save something else, add a field to `Settings` in `settings.h`, a line that writes it in
`write_settings`, and a line that reads it in `read_settings`. A file saved before the new field
existed does not have it, and stops the game with `the document has no` and its name; delete the
file, or read the field only when `root.has("its_name")` is true, and keep the default otherwise.
